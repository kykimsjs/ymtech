# Design Taste — ymtech

목표는 "AI가 만든 기업 홈페이지"처럼 보이지 않는 화면이다. 예쁘게 꾸미는 것보다 **이 회사에만 있는 재료를 정확하게 보여주는 것**이 우선이다.

## 0. 시작 전에 읽을 것

- `docs/YM이노테크_홈페이지_기획안.md`: 타깃, 메시지, 사이트맵
- `docs/reference-analysis.md`: 레퍼런스 5곳 분석, 쇼케이스 방향 A~D
- `app/globals.css`: 디자인 토큰. 색·서체·간격은 여기 있는 것만 쓴다.
- `components/ui/`: 이미 있는 컴포넌트를 먼저 쓴다.

## 1. 방향을 하나 정하고 끝까지 민다

작업 전에 아래 세 줄을 먼저 적고 시작한다.

```
방향: (reference-analysis.md의 A 현장 기록형 / B 라이브 관제형 / C 기술 문서형 / D 제품 오브젝트형 중 하나, 또는 새 방향)
이 회사에만 있는 재료: (예: 분전반 내부 장착 사진, 3상 전류 파형, 10초 차단, KETI ±2%)
이 화면에서 버릴 것: (방향과 안 맞는 요소)
```

- 한 화면에 방향을 두 개 섞지 않는다. 예를 들어 "어두운 관제실 + 밝은 친환경 일러스트" 같은 조합은 피한다.
- 쇼케이스를 여러 개 만들 때는 서로 다른 방향을 고른다. 색만 바꾼 변형은 쇼케이스로 치지 않는다.

## 2. 금지 목록

하나라도 보이면 고친다. 괄호 안은 이 프로젝트 첫 시안에서 실제로 나왔던 것이다.

### 비주얼
- 제목에 그라데이션 텍스트 (첫 시안의 "에너지 최적화까지")
- 제품 뒤에 흐릿한 빛 번짐(blur glow) 덩어리 (첫 시안의 제품 사진 뒤 효과)
- 다크 네이비 + 라디얼 그라데이션 히어로를 기본값으로 쓰는 것 (첫 시안)
- 사진 위에 떠 있는 가짜 상태 카드와 지어낸 수치 (첫 시안의 "220V · 12.4A · 24.1°C")
- 보라·파랑 그라데이션 배경, 글래스모피즘(반투명 블러 카드) 남발
- 3D 로봇, 뇌, 회로, 지구본, 빛나는 네트워크 선 같은 'AI' 상징 이미지
- 내용과 관계없는 스톡 사진: 악수, 도시 야경, 웃는 직원, 잠든 아이
- 육각형·원형 아이콘 다이어그램, 이모지 아이콘

### 레이아웃
- "둥근 사각형 안 아이콘 + 제목 + 설명 두 줄" 카드를 3열로 반복 (첫 시안의 핵심 소구점)
- 모든 섹션 앞에 "선 + 영문 대문자" 소제목(eyebrow) (첫 시안 전체)
- 모든 섹션을 가운데 정렬, 모든 섹션 위아래 여백이 같은 리듬
- 카드 안에 카드, 테두리 안에 테두리
- 풀페이지 스크롤(스크롤 가로채기), 무한 슬라이더 자동 재생
- 아무 근거 없는 "Why Us", 지어낸 고객 후기, 지어낸 고객사 로고

### 타이포그래피
- 한글 굵기 100~300을 본문이나 어두운 배경에 쓰는 것
- 한 화면에 서체 세 종류 이상
- 한글 본문에 자간(letter-spacing)을 넓히는 것

## 3. 대신 이렇게 한다

### 레이아웃
- **내용 길이가 레이아웃을 정한다.** 항목이 2개면 2열, 4개면 4열. 3열에 맞추려고 항목을 만들지 않는다.
- 비대칭 그리드를 기본으로 한다. 예: 제목 5칸 + 본문 7칸, 사진 8칸 + 캡션 4칸
- 섹션마다 밀도를 다르게 한다. 숫자 하나만 크게 있는 여백 많은 섹션 다음에 표가 빽빽한 섹션이 와도 된다.
- 왼쪽 정렬을 기본으로 한다. 가운데 정렬은 짧은 문장 하나일 때만 쓴다.

### 색
- CI 블루(`brand-500`)는 **글자·선·작은 면적**에 쓴다. 넓은 배경을 블루로 칠하지 않는다.
- 상태 색(`success`·`warning`·`danger`)은 **실제 상태를 표시할 때만** 쓴다. 장식으로 쓰지 않는다.
- 한 화면에 강조색은 하나만 쓴다.
- HEX를 직접 쓰지 않는다. 토큰이 없으면 `globals.css`에 먼저 추가한다.

### 서체
- 한글 제목은 Leferi(`font-display`, `font-base`), 본문은 Pretendard(`font-sans`)
- 본문은 행간 1.7~1.8, 한 줄 40~45자 이내(`max-w-[42em]` 안팎)
- 숫자는 `tabular-nums`로 쓰고 단위를 붙이며, 가능하면 기준일을 적는다 (예: 2026.10 기준)

### 이미지
- 이 회사의 실제 사진만 쓴다: 제품, 분전반 설치, 온실 현장, 웹 플랫폼 화면
- 사진이 없으면 스톡으로 채우지 않는다. 회색 면에 `사진 필요: 분전반 내부 설치 모습`처럼 **무엇이 들어갈지 적은 자리 표시**를 둔다.
- 다이어그램은 실제 구성을 그린다: MCCB → 에코-비탈 모듈 → RS-232/LAN → 웹 플랫폼

### 데이터·대시보드 표현
- 예시 수치를 쓰면 화면에 `예시 화면`이라고 표기한다.
- 차트는 실제 단위·축·범례를 갖춘다. 장식용 곡선을 그리지 않는다.

### 움직임
- 의미 있는 곳에만 쓴다: 상태 변화, 차단 동작, 데이터 갱신
- 150~250ms, `ease-out`. `prefers-reduced-motion`이면 끈다.
- 스크롤할 때마다 요소가 페이드업하는 효과를 모든 섹션에 넣지 않는다.

## 4. 검증 루프 (생략하지 않는다)

1. 빌드 후 실제 브라우저에서 **390px, 768px, 1440px** 세 너비로 스크린샷을 찍는다.
2. 2장의 금지 목록을 하나씩 대조한다. 가로 스크롤, 넘친 텍스트, 겹친 요소도 확인한다.
3. 가장 거슬리는 문제 세 개를 고친다.
4. 최대 세 번 반복한다. 세 번 뒤에도 남은 문제는 숨기지 말고 보고한다.

## 5. 보고할 때

- 고른 방향, 참고한 레퍼런스, 이 회사 재료를 어디에 썼는지
- 자리 표시로 남긴 사진·자료 목록 (클라이언트에게 받아야 할 것)
- 화면 문구는 `korean-copy` 스킬 기준으로 따로 점검한다.
